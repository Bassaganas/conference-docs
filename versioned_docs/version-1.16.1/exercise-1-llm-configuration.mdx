### ⚙️ Core Model Parameters You Should Tune

<ul>
  <li><b>Temperature</b>: start at <code>0.2-0.4</code> for deterministic testing tasks; increase for creative generation.</li>
  <li><b>Top P</b>: keep at <code>0.8-1.0</code>; avoid changing both Top P and Temperature aggressively at the same time.</li>
  <li><b>Max Tokens</b>: cap output to control cost and reduce noisy long answers.</li>
  <li><b>Frequency/Presence Penalties</b>: use low values first; they can reduce repetition but also remove needed terminology.</li>
  <li><b>Context Window</b>: ensure your model can handle prompt + retrieved chunks + expected answer length.</li>
  <li><b>Timeout/Retry</b>: set explicit limits so workflow runs fail fast and are easier to debug.</li>
</ul>

<div style={{ background: '#ecfeff', border: '2px solid #06b6d4', borderRadius: '8px', padding: '1em 1.5em', margin: '1em 0' }}>
  <b>Recommended baseline for this workshop:</b> Temperature <code>0.3</code>, Top P <code>0.9</code>, and a moderate max token cap. Change one parameter at a time and re-run the same validation questions.
</div>

### 2. Prepare Your Local/Self-Hosted Endpoint

Use one of these patterns:

<ul>
  <li><b>Ollama on the same host or network as Dify</b>: install Ollama, run <code>ollama pull qwen2.5:1.5b</code>, and use the Ollama provider's native endpoint.</li>
  <li><b>Ollama on your laptop with remote Dify</b>: do not enter <code>localhost</code>. Dify resolves that name inside its own container or server. Use an authenticated HTTPS gateway or a private network route that Dify can reach.</li>
  <li><b>LM Studio</b>: start its local server mode and use its documented OpenAI-compatible endpoint only when Dify can reach that endpoint.</li>
  <li><b>Self-hosted vLLM/TGI</b>: expose a private, authenticated endpoint reachable from the Dify runtime network.</li>
</ul>

Never expose Ollama's unauthenticated port directly to the internet. Put authentication and TLS in front of a remote endpoint, and use the smallest model and context window that meet the exercise goal.

For the workshop capture, the local setup used:

1. `ollama serve`
2. `ollama pull qwen2.5:1.5b`
3. A loopback-only proxy on `127.0.0.1:8787` that forwards to Ollama and rejects requests without a bearer token
4. `cloudflared tunnel --url http://127.0.0.1:8787`
5. Two quick checks:
   - unauthenticated `GET /api/tags` returns `401`
   - authenticated `GET /api/tags` returns `200`
