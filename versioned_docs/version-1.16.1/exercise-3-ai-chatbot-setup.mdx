## 🛠️ Step 1: Start a New Chatflow

<ol style={{ marginBottom: '2em' }}>
  <li>
    Click <b>Studio</b> in the left sidebar, then <b>Create</b> → <b>Create from Blank</b>.
    <Shot src={require('../static/img/dify/1.16.1/ex3/chatflow-landing.png').default} alt="Studio with the Create menu open and Create from Blank underlined" caption="Studio → Create → Create from Blank" />
  </li>
  <li>
    Select <b>Chatflow</b>, give it a meaningful name and description, and click <b>Create</b>.
    <Shot src={require('../static/img/dify/1.16.1/ex3/chatflow-create.png').default} alt="Create from Blank dialog with the Chatflow app type selected" caption="Chatflow selected, with name and description" />
  </li>
  <li>
    A new Chatflow already contains <b>User Input → LLM → Answer</b>. Open the <b>LLM</b> node and select <b>gpt-35-turbo-16k</b> as the model. Then write a <b>SYSTEM</b> prompt, and use the <b>{'{'}x{'}'}</b> button (or type <code>{'{'}</code>) to insert the <b>Context</b> block.
    <div style={{ background: '#e0f2fe', border: '2px solid #38bdf8', borderRadius: '8px', padding: '0.8em 1.2em', margin: '1em 0' }}>
      The user's question is already in the <b>USER</b> message (<code>User Input / query</code>), so the SYSTEM prompt only needs your instructions and the context.
    </div>
    <Shot src={require('../static/img/dify/1.16.1/ex3/chatflow-llm-config.png').default} alt="LLM node with the model selected, a SYSTEM prompt containing the Context block, and the USER message holding query" caption="LLM node: SYSTEM prompt with Context, USER message with query" />
  </li>
  <li>
    Click <b>Preview</b> and ask a question. Expand <b>Workflow Process</b> above the answer to see each node that ran, with its duration and token count.
    <Shot src={require('../static/img/dify/1.16.1/ex3/chatflow-preview.png').default} alt="Preview panel with the Workflow Process expanded: User Input, LLM and Answer" caption="Preview with the Workflow Process expanded" />

### Check the answer against its sources

Run this risk-oriented query:

> Which Jira issue creates a backward-compatibility risk around unknown JSON
> properties, and what should we test?

The answer passes only if it names REST-266, explains the compatibility risk, gives test ideas supported by the retrieved context, and shows source citations.

<Shot src={require('../static/img/dify/1.16.1/ex3/grounded-risk-answer-citations.png').default} alt="Answer naming REST-266 as the backward-compatibility risk, with citations highlighted" />

Now expand <b>Workflow Process</b> and click the <b>Knowledge Retrieval</b> step. <b>INPUT</b> shows the query that was searched:

<Shot src={require('../static/img/dify/1.16.1/ex3/knowledge-retrieval-trace.png').default} alt="Expanded Knowledge Retrieval step showing its duration and the query input" />

Scroll down to <b>OUTPUT</b>. It lists the chunks that were retrieved and passed to the LLM. Here the top chunk is REST-266, including the aliases and example questions that advanced ingestion added. Checking what was retrieved is stronger evidence than an answer that merely sounds right.

<Shot src={require('../static/img/dify/1.16.1/ex3/knowledge-retrieval-trace-output.png').default} alt="Knowledge Retrieval output showing the REST-266 chunk with its aliases" />

## 🛠️ Step 5: Augmenting Your Prompt

### 1. Current Behaviour: Out-of-Scope Answers

Ask something that has nothing to do with your project: <code>Why is the sky blue?</code>

<div style={{ background: '#fef2f2', border: '2px solid #ef4444', borderRadius: '8px', padding: '1.2em 1.5em', margin: '1.5em 0', fontWeight: 600, color: '#b91c1c', fontSize: '1.1em' }}>
  <span style={{ fontSize: '1.3em', marginRight: '0.5em' }}>⚠️</span>
  <b>Current Behaviour:</b> The chatbot happily explains Rayleigh scattering, and even shows Jira citations that have nothing to do with the answer.<br />
  <span style={{ fontWeight: 400, color: '#991b1b' }}>Two things go wrong: the prompt doesn't tell the LLM to stick to the context, and the retriever always returns its top chunks, even when none are relevant.</span>
</div>

<Shot src={require('../static/img/dify/1.16.1/ex3/chatflow-out-of-scope.png').default} alt="Answer explaining why the sky is blue, with unrelated Jira citations highlighted" />

### 2. Preventing Hallucination and Out-of-Scope Answers

<div style={{ background: '#fffbe8', border: '2px solid #facc15', borderRadius: '8px', padding: '1.2em 1.5em', margin: '1.5em 0', fontWeight: 600, color: '#854d0e', fontSize: '1.1em' }}>
  <span style={{ fontSize: '1.3em', marginRight: '0.5em' }}>🔍</span>
  <b>Fix the prompt:</b> Tell the LLM to answer only from the provided context, and give it an exact reply to use when the context doesn't help.
</div>

<details>
  <summary style={{ fontWeight: 'bold', cursor: 'pointer', color: '#ca8a04' }}>Copy-paste Prompt Example</summary>
  <div style={{ margin: '1em 0' }}>
    <CodeBlock language="text">{`Answer in a clean, professional tone. Be concise but precise.
Only answer questions using the information provided in the context below.
If the context does not contain relevant information to answer the user's question, reply exactly:
"I'm sorry, I can't find relevant information in the project documentation to answer that."

Context:
{{#context#}}
`}</CodeBlock>
  </div>
</details>

Paste it into the LLM's SYSTEM prompt, replacing what's there. Dify turns <code>{'{{#context#}}'}</code> into the Context block. Ask again:

<Shot src={require('../static/img/dify/1.16.1/ex3/chatflow-fix-hallucinations.png').default} alt="Answer to Why is the sky blue? returning the no-match reply" />

The answer is fixed, but the unrelated citations are still there, because the retriever still returns chunks. To fix that too, open the <b>Knowledge Retrieval</b> node, click <b>Retrieval Setting</b>, and turn on <b>Score Threshold</b> at <code>0.5</code>. Chunks scoring below the threshold are dropped. Out-of-scope questions then retrieve nothing, while REST-259 and REST-266 still return their issues.

<Shot src={require('../static/img/dify/1.16.1/ex3/retrieval-score-threshold.png').default} alt="Retrieval Setting dialog with Score Threshold enabled at 0.5" caption="Retrieval Setting: Score Threshold enabled" />

### 3. Improving Our Prompt and Results

<div style={{ background: '#ecfdf5', border: '2px solid #22c55e', borderRadius: '8px', padding: '1.2em 1.5em', margin: '1.5em 0', fontWeight: 600, color: '#166534', fontSize: '1.1em' }}>
  <span style={{ fontSize: '1.3em', marginRight: '0.5em' }}>✨</span>
  <b>Improving Our Prompt:</b> Refine your prompt to be more specific and structured for your use case. For example, you can:
  <ul style={{ fontWeight: 400, color: '#166534', marginTop: '0.7em' }}>
    <li>Define the assistant's role (e.g., "You are a software testing assistant helping engineers understand Jira issues, project documentation, and related work.")</li>
    <li>Describe what the context chunks contain (a Jira key and aliases, summary, type, status, assignee, and description)</li>
    <li>Ask the assistant to organise key information, highlight relevant fields, clarify technical areas, and explain what it means for testing</li>
    <li>Clearly state how to handle missing information (e.g., mention what's known and what isn't)</li>
  </ul>
  This level of detail helps the LLM provide more accurate, relevant, and actionable answers.
</div>

<Shot src={require('../static/img/dify/1.16.1/ex3/chatflow-prompt.png').default} alt="LLM node with the improved software testing assistant SYSTEM prompt" />

<details>
  <summary style={{ fontWeight: 'bold', cursor: 'pointer', color: '#7c3aed' }}>Sample Prompt for Students</summary>
  <div style={{ background: '#f3f0ff', border: '2px solid #7c3aed', borderRadius: '8px', padding: '1em 1.5em', margin: '1em 0' }}>
    <CodeBlock language="text">{`You are a software testing assistant helping engineers understand Jira issues, project documentation, and related work.

Only answer using the information provided in the context below. Never use outside knowledge or speculation.
If the context does not contain relevant information, reply exactly:
"I'm sorry, I can't find relevant information in the project documentation to answer that."

Each context chunk describes one Jira issue: its key and aliases (for example REST-266, Issue 266), example questions, summary, type, status, assignee, dates, and description.

Your reply should:
- Give a concise, professional summary of the issue or topic
- Highlight relevant fields (summary, type, status, assignee, etc.)
- Mention related issues when they appear in the context
- Clarify technical areas (for example endpoints, APIs, modules)
- Explain the relevance for testing (for example new test cases, regression risk, feature readiness)

If information is missing, say what is known and what isn't.

Context:
{{#context#}}
`}</CodeBlock>
  </div>
</details>

### Keep a version you can go back to

Each publish saves a snapshot in the version history, so you can experiment in Exercise 4 and still roll back:

1. Publish only after the grounding checks in Step 4 and Step 5 pass.
2. Click the clock icon at the far right of the top bar to open <b>Versions</b>.
3. Open the <b>⋯</b> menu on the latest version, choose <b>Edit Info</b>, and give it a short title and release notes describing what you checked.
4. Select a version to preview it. <b>Restore</b> copies it back into your draft.
